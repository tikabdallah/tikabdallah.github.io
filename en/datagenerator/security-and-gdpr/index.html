Security and GDPR

Last updated: October 6, 2026

Dahoni Data Generator makes no external callouts: every record it generates stays inside your Salesforce org, with nothing sent to a third-party server.

No data leaves your org

Data Generator runs entirely in Apex, inside your Salesforce org. It makes no external API calls and does not communicate with any service hosted outside Salesforce, whether to generate records or to store a configuration. Templates, generation rules, and the run history are stored in custom objects within your org.

A safeguard against production

Data Generator is built for test environments: Developer Orgs, scratch orgs, and sandboxes. A built-in safeguard prevents accidental generation on a production org.

Synthetic data, not real data

Data Generator creates fictitious records from rules you configure (text type, phone format, date range, picklist distribution, blank value rate). It does not copy or import any real data from another org. The configuration you define, not an existing dataset, determines what gets generated.

Access control through a permission set

Using Data Generator requires the "Data Generator User" permission set. You keep full control, through Salesforce's standard tools, over who can create, run, and delete generations in your org.

Deleting generated data

Every generation run can be deleted in one click, along with every record it created. This keeps test data from piling up in an environment.

What this page does not cover

This page describes Data Generator's technical architecture (no external callouts, production safeguard, access control). It is not legal advice on your overall GDPR compliance, which also depends on how you configure and use the app within your own org.
